## Implemented interfaces

| Module | Public entry points and contract |
| --- | --- |
| `cache` | `prepare_episode_cache`, `load_episode_cache`, `episode_factory`, `CachedTrainingModel`, `attach_training_cache`, `e3_source_sha256`. A strict JSON/numeric tensor cache preserves Episode content and metadata, checks on-disk hashes on every load, has independent disk/LRU ceilings, and returns new Episode objects. Training-only terminal encoding and raw feature memoization bind input, E1/E3 source, writer/reader, shape, reference time and feature version; misses call E1 methods, and hits are checked on fixed controls. Stream encode bypasses the cache. |
| `wire` / `worker` | `export_statics`, `encode_request`, `isolated_read_batch`, `worker_main`. At most 64 history/query pairs per fresh interpreter. Strict schemas, array/frame ceilings, source/writer/request/response hashes and identity checks precede reconstruction. The reader is reconstructed from statics; labels and fit history stay in the parent. Subclasses, extra writer fields and changed writer constants are rejected. The worker verifies input/method immutability and installs the disk/network/process audit guard after trusted imports. Each attempted batch has an atomic journal; retries receive unique names. |
| `comparators` | `build_controls`, `laguerre_control`. FP64 exact, recent, latest LRU, reservoir and shared buckets use shape-specific persistent budgets. Latest LRU is capped at the public K-key universe, with unused bytes and the larger byte-fitting capacity reported. The independent Laguerre control steps each event and compares recovered Jet state and predictions within `1e-12`. |
| `study` | `study_manifest`, `probe_feasibility`, `run_development`, `freeze_score_policy`, `score_results`, `select_candidate`, `persist_score_rows`, `load_score_rows`, `evaluate_panel`. Manifest fixes the 12-cell, 768-training/192-development inventory and 36 readers; the study expects 40 fits including four selected prefix refits. Probe does one declared tiny fit and one worker batch, then forecasts full work. Development uses finite phase allocation, journals failed/incomplete attempts, revalidates completed model and row artifacts on resume, and records candidate, prefix, control, row, cost and admission references. `evaluate_panel` is the generic replayable factory boundary for E4: pass a loaded base model or registered control, frozen policy, training statistics, output directory, finite allocation and worker limits; it persists normalized rows and returns score/cost/reference records. |
| `timing` | `timed_pipeline`, `measure_one_event`, `break_even_queries`, `benchmark`. The benchmark enforces three warmups, 12 separated paired blocks and Q=1/8/64. It records preprocessing, chunked stream ingestion, in-process read/output, one-event continuation latency, cold worker startup, request serialization and worker round trip. Summaries have p50/p95 and block bootstrap intervals. Break-even requires a positive time saving and an accuracy-qualified candidate. |

The E4 caller should freeze its own real-data policy with `freeze_score_policy(factory(), tasks=..., manifest_hash=...)`, validate an E1 model with `load_model`, call `evaluate_panel(...)`, then reload `rows_ref` through `load_score_rows`. The policy's full and label-only eligible inventory hashes are retained. Numeric aggregation requires every declared primary task in each history; unsupported targets are diagnostic rows and prediction failures on valid targets remain scored. A mean-only secondary population uses an explicit mean-only policy and weights. Beijing observed-event episodes derive the scoring regime from their preparation/normalization metadata without mutating the Episode.

Every normal evaluator history uses `mode='stream'` chunks of at most 128, advancing the underlying recurrence through every event. It checkpoints before each chunk and, after a numerical error or nonfinite state, replays that chunk one event at a time to record the earliest triggering offset. Infrastructure errors stop the run. Stream audits retain per-history chunk/input/state digests, checkpoint copy bytes/time and replay work. The Laguerre control records its independent coordinate/conversion work. Worker batches contain only statics, snapshots and queries.

Normalized row files store each scoring policy once under its canonical hash; individual rows reference it. Reload checks file bytes/hash, normalized structure, policy hashes and references, then restores the identical core row shape before aggregation. This avoids repeating a large policy inventory in every row. Row, cache, worker journal and other output bytes count toward disk admission.

## Feasibility and limits

The production profile entails 36 candidate fits plus four prefix fits, and 46 development panels (36 candidates, four prefixes, six controls). At 192 histories per panel that is 8,832 full-history development replays; with the fixed 128/512/2048 length mix, approximately 7.9 million underlying event steps before fitting, controls, metadata scans, worker startup, scoring, serialization and I/O. The unit probe proves the interfaces execute on a tiny population; it cannot establish a wall-time, disk or memory budget for the full profile. `probe_feasibility` emits work counts and measured tiny-fit/batch timings for Root's separate admission decision. Source tests did not run the actual 36-fit profile, protected panels, or the full benchmark.

The isolated worker is an audited accidental-leak boundary rather than an adversarial OS sandbox. No test has established that the full-profile score row volume, cold-worker startup or E1 repeated row-loop/hashing work meets an allocated runtime. The live-handshake RSS proxy is conservative and cannot identify inference workspace. The benchmark API has fake-clock and unit checks; its full 12-block measurement still requires an explicit timing allocation. These limits are visible in manifests and admission records instead of being silently treated as successful science.

## Independent review fix round 2 — 24 October 2026

The scoped FIX1 rereview (`.superpowers/sdd/2026-10-16-famjet/e2e-task-3-fix1-review.md`) accepted I1–I5 and M1/M2, then identified one new Important integration regression, R1: a reused cache was compared with *unused* phase disk bytes although `_admit` had already counted that cache in total used workspace bytes. FIX_BASE is `c8f95d6a11bb2c078258a34315137d4a0927bdae`; source/test fix commit is `a3ffade3`. `_cache_for` now has separate `limits['disk_bytes']` (configured **total cache ceiling**) and optional `incremental_disk_bytes` (**unused phase space for new writes**). For an existing cache, it verifies ordered history/spec hashes, source/hash identity, fixed LRU ceiling and measured cache bytes against the configured total ceiling, then returns without regeneration or rewriting. Whole-directory `_admit` checks the phase total. For a new cache, `prepare_episode_cache` receives the smaller of configured total and incremental allowance. Probe and development callers pass both values separately for training and development caches; the development configured total is reduced by the already-counted training cache. An actually too-small configured total remains rejected, and new writes still fail when incremental space is insufficient.

Two caller-level regressions prebuild both real tiny-unit cache directories, set unused phase disk space below **each** cache's size while keeping the entire output within the phase allocation, block episode generation, and stop immediately after both reopens. They verify the original cache file hashes and modification times remain identical. A cache helper regression verifies zero incremental space permits reuse while a new cache fails under a 128-byte incremental allowance. The first `red-r1-callers` run exposed an overly high test setup threshold and is preserved; `red-r1-callers-2` demonstrates the actual source failure in both probe and development callers. `green-r1-callers` and `cache-total-incremental` passed.
