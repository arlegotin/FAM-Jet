## Implementation and API choices

`KernelProjection(rates, family, t_ref, prior_scale=5224., ridge=...)` is an FP64 CPU module with no parameters. Its small general-basis arithmetic API supports analytic controls; **production wrapper admission** is restricted to fixed Jet4/Bank8, one head, K16/V8, full caller-order log grids and the adopted prior/time-unit ratio. Supplied rate bits are retained rather than replaced with a regenerated grid. Existing kernels own writes, causal advance (including the Jet moment cross-term), snapshot schemas and persistent bytes.

The reader exposes `window_vector`, `coefficients`, `window`, `factor_diagnostics` and exact `from_statics` reconstruction. It computes positive closed exponential integrals with lower-endpoint shifts, convergence-controlled small-product series, large-product limits and log coordinates. Gram entries include both canonical Jet rate factors. The ridge acts in the canonical diagonal Gram metric. The spectral construction rejects every negative computed eigenvalue; there is no clamp or alternate factorization. Static validation checks the exact Gram/diagonal/inverse-shift relationships, eigenvector orthogonality and normalized factor residual <=1e-12. Each coefficient solve checks its normalized residual <=1e-12; condition estimates and minimum eigenvalues are inspectable without a retained query cache. These internal checks are not substitutes for the future independent pointwise gates.

`KernelReadModel(kernel, ridge, fit_provenance, target_statistics, prior_scale=5224.)` requires bounded, validated existing training metadata with matching writer/time identities and frozen mean/contrast means. It derives a registered 2-by-8 fallback buffer. It performs no fitting, file lookup, generator call, reference-history lookup or label lookup. Test metadata is explicitly synthetic unit data; no test statistic is an adopted production fallback. The actual accepted fallback export/hash/seal remains unverified and blocking for later execution. Prior5224 comes from the unchanged training-only summary `docs/research/task18-training-horizon-statistics.json`, SHA256 `1878d965024ed63d79fd2c0d3a9156ac2facbd10dcda218943c0a7af0b68a95c`; its 6144-history observed maximum is not a factual span bound.

The wrapper implements the MemoryMethod init/encode/advance/read/byte interface. State parameter identity remains exactly the kernel writer/rate identity; the exported whole-method identity additionally binds reader factors, ridge/prior, epsilon/floor/cancellation policy and fallback metadata. Both mean and contrast use raw numerator/normalizer contractions and identical window coefficients for each. Contrast evaluates recent first, then adjacent older, and subtracts **two separately normalized ratios**. There is no count/ratio clipping, positivity repair, epsilon search, hidden-history adaptation or learned override.

Strict numerical guard order is quarantine/nonfinite input/nonnegative canonical normalizers, then negative/floor mass, cancellation, division/result finiteness. The epsilon and floor are1e-8; the cancellation factor is64*2^-53. Failure codes enumerate eligible, quarantined, nonfinite input, negative normalizer, negative mass, mass floor, cancellation and nonfinite result. Failed active queries return the frozen task mean with failure flags intact. The original snapshot stays byte-exact; a nonfinite row remains poisoned and all later reads on it remain quarantined. Existing external runner quarantine and existing encode rejection of nonfinite state were unchanged. Empty/absent mass fails eligibility without fabricated targets; an empty query batch is supported.

`ReadResult.support` is NaN to represent unavailable factual support/confidence; `factual_support_available` is false. `numerical_eligible` and the existing `prediction_valid`/`numeric_supported` integration fields refer only to arithmetic usability. Positive reconstructed mass never claims an observed event count or support probability. Numeric JSON uses the existing null representation for NaN. No target labels or losses are created by this component.

## Closed worker and ownership

The existing clean worker receives only its existing numeric snapshot/public-query transport plus the new bounded closed numeric static schema. Registration accepts precisely the wrapper and reader classes. Unknown schema fields, hidden instance fields, hooks, callables, undeclared buffers and arbitrary ownership fail existing constructor-tree comparison; new query attributes are explicitly rejected before transport can silently strip them. Reference-event helpers were not added to the worker. Existing registered TaskModel construction was kept intact and covered by affected-node tests.

Reconstruction imports **exact tensor bytes** for the six reader arrays and never runs eigendecomposition. Those arrays are alpha, Gram, diagonal, eigenvectors, unshifted eigenvalues and inverse shifted eigenvalues. No per-history coefficient/query/factor cache or additional persistent history field is retained. Test static round trips compare every state_dict tensor record and complete exported records byte-for-byte for both families; worker arithmetic compares at the adopted atol=rtol1e-12.

Wrapper delegation preserves this exactly. `ownership_ledger()` first validates the closed export, then walks every reachable instance/config Python object (including nested dictionaries, schemas and training summaries), deduplicates Python identities and distinct full tensor backing stores, and reports Python bytes, tensor logical/storage bytes, total owned bytes and serialized bytes separately. No NumPy arrays are retained; undeclared arrays fail export. The existing model/state ledger checks backing completeness and graphs. All new retained tensors are registered buffers and owned clones.
