# Task13 development fixture corrections

The initial kernel test failed at import because `famjet.memory.hippo` did not exist (expected Task13 RED). Integration next produced4 expected missing PolynomialConfig/config_documents_equal failures. After implementation,3 integration fixtures failed because they inherited cache_limit_bytes0 from the jet smoke config while requesting a nonempty gap alphabet. The corrected polynomial fixture explicitly declares1024 bytes; production rejects an insufficient cache budget before allocation.

An added unit/shift fixture originally performed `timestamps + 2**60` directly on synthetic float64 timestamps. That destroys unit gaps before the adapter sees them; both full-model reader variants consequently failed. The preserved corrected test first asserts each source event/query time is exactly integral, converts to int64, and then adds2**60. No production time arithmetic or numerical tolerance was changed to fit the erroneous input.

The first snapshot roundtrip fixture omitted snapshot_from_record's mandatory expected_parameter_hash argument and raised TypeError; the corrected fixture supplies the actual writer hash. Additional REDs were missing scalar allocation support, missing call_preparation_cost, and direct optional RateConfig dictionary input reaching AttributeError. Scalar order/tau normalization, pure work inventory and strict actual optional dataclass validation were then implemented. All original assertions and intended invalid-input checks remain in tests/test_hippo.py; failures and corrections are not numerical acceptance evidence.
