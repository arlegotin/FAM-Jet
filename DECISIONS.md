## Task 2 implementation choices — 16 October 2026

- Version-1 event tensors use [history,event,channel]; queries use [history,query,channel]. CPU float64 or checked int64 tick timestamps are distinct from recurrence tensors. The first active event has zero intra-batch gap; streaming adapters must check it against a prior snapshot. Missing observations advance time, padding does not.
- Per-channel missingness requires `normalization="independent"`; shared normalization permits only a uniformly observed or uniformly missing vector event. Key IDs accept nonnegative CPU int64 for one-hot data and full CPU uint64 for dense identities; ordinal event/query IDs stay int64. No float conversion of public IDs is permitted.
- Namespaced seeds hash the versioned canonical JSON object containing root, namespace and identity, then use the low 63 bits of the first eight SHA-256 bytes (big-endian). Seed derivation never mutates global RNG state.
- Configuration records are frozen dataclasses with required resolved fields. Confirmation scientific payloads remain explicit JSON values pending later manifest-schema gates; no pilot result or scientific default is invented. JSON resolved files use the JSON parser to preserve scientific-notation numbers, while YAML rejects duplicate fields.
- Atomic JSON serializes finite values before creating a sibling temporary file, fsyncs the file and replaces the destination. Null/status remain explicit; the helper does not create checkpoint backup/serialization policies or claim power-loss durability for the parent directory.

## Task 3 oracle/statistics handoff — 16 October 2026

- Exact task registry: `mean`, `contrast`, `latest`, `change_sign` return CPU FP64 [B,Q,V]; `presence`, `interval_support` return [B,Q,1]; `corrected_categorical`, `random_binding` return [B,Q] category indices. Output families must be homogeneous per batch. `interval_support` asks whether the single supplied interval has every coordinate observed; contrast support already requires both intervals. Unrecognized task names raise rather than inventing labels.
- Exact identity uses raw public key IDs, never approximate feature overlap. Gating and keys do not weight raw observed-event means. A present no-write event advances time but contributes no target observation. Latest selects the latest event with any observed coordinate by `(timestamp,event_id)`, then requires its whole value vector observed; it never carries forward missing coordinates from a different event. Independent-coordinate means count each coordinate separately and whole-query support requires all coordinates.
- Arithmetic/fact missing labels use NaN tensors, null `metadata.targets`, and abstention. Binary presence/interval-support labels are valid 0/1 even when factual `supported` is false; `metadata.target_valid` and `abstained` express this distinction. Training statistics include all active binary labels irrespective of Episode.supported. Other tasks include supported labels only. Downstream generators/scorers must preserve this task-dependent validity contract.
- `fit_target_statistics` requires metadata split exactly `training`. Within a task, each supported query contributes once. Mean is coordinatewise; coordinate population variance uses ddof=0 about that coordinate's own mean. The SINGLE task scale squared is the arithmetic mean of those variances across ALL coordinates, including exact constants. Example [2,7],[6,7] gives mean [4,7], variances [4,0], pooled variance 2, scale sqrt(2). This is not variance of flattened coordinates. Exact constant-coordinate flags tell the future scorer to report those coordinates separately in absolute error. All-constant tasks have scale null, requiring absolute-error handling, not an invented epsilon. No-supported tasks have explicit null/status. Class distributions use all 32 category bins or both binary bins, including zero-count bins; categorical fallback uses priors, not the numeric mean of category IDs.
- The numerical checker uses seeded PCG64 with lognormal gaps mean=0/sigma=1, uniform [0.05,1] keys, Normal(0,1) values, Uniform[0,1] gates, four geometric rates [0.001,1], and an independent diagnostic recurrence/equivalent-coordinate loop. Golden fixture prefixes and the observed environment are saved. Rate finite differences use relative symmetric rate spacings; the normalized derivative uses symmetric log-rate spacing 1e-5 and epsilon 1e-8. The ordinary FP64/FP32 tolerances remain 1e-12/1e-12 and 1e-5/1e-6; finite-difference/Hermite diagnostics have separate declared bounds. A single diagnostic is not universal numerical evidence.

Task 3 round-1 time correction: `exact_time_difference(newer: int | float, older: int | float) -> int | Fraction` in `famjet.eval.oracle` preserves full Python integer ticks and exact binary values of finite float timestamps. Integer pairs subtract as integers; any float operand uses rational subtraction, avoiding implicit int-to-float coercion. Oracle half-open comparisons consume these exact ages directly. Accepted mixed time dtypes are retained. Streaming adapters must preserve this represented-value policy when validating time or comparing tick boundaries; converting exact ages to floating point for numerical decays is a separate kernel choice, not valid for exact target membership. Existing float timestamps cannot recover tick information already lost before entering the API.

## Task 4 kernel implementation choices — 16 October 2026

- Core state is `[B,H,J,K,V+1]`, rates `[H,J]`, key `[B,H,K]`, value `[B,H,V]`, gate `[B,H]`, elapsed gap `[B]`, and actual-write mask `event_present[B]`. Decay always follows delta, independently of the write mask: a real no-write gap is delta>0/false and padding is delta0/false. Raw EventBatch.present controls timestamp/padding preparation; EventValidation.write_mask controls impulses. Raw EventBatch is explicitly head one with shared vector observation/normalization; independent-coordinate batches are rejected. A later independent-coordinate method must allocate/count separate normalizers explicitly. This corrected round-1 ruling supersedes the initial conflation of core write presence and raw nonpadding presence.
- Per-anchor structured feature order is `r[V], dlog_rate_r[V], log1p(z), b/(z+eps), log(lambda*t_ref), support`, flattened over heads/anchors. Raw `u,h,z,b`, exact dimensionless/physical ages, per-anchor support and query failure are diagnostics. Query numerical support means at least one anchor exceeds the configured floor and has finite arithmetic. This is distinct from factual target support and learned abstention. Exact unsupported ages use a safe denominator before division. Invalid structured arithmetic is zero-filled and flagged; no training-mean prediction fallback is implemented here.
- Evaluate the derivative as `(r*b-h)/(z+eps)`, centering before division to reduce cancellation. The direct derivative contract still requires rate-independent writes and epsilon. Fixed raw encoding accepts no query arguments; no claim is made about arbitrary user-supplied tensor dependency graphs.
- Ordinary elapsed-time products run on the state device. If a finite CPU FP64 gap exceeds the state's representable range, explicitly multiply on CPU FP64 before casting weights. Transfer an MPS rate to CPU first, then promote: the installed torch silently zeroed `1e-30` with combined `.to(device='cpu',dtype=float64)`. This rare explicit host-time path preserves gradients and is not implicit MPS fallback. Reference extraction follows the same transfer-before-promotion rule.
- Public reads compute exact represented-value CPU gaps before numerical conversion, independent of query order/padding; no query modifies saved state. Snapshot payload includes z/h, per-history SHA-256 identities, a time-unit hash and last event IDs; last times, validity and offsets remain CPU tensors. Logical bytes include all these tensors, packed parameter hash and schema integer. This accounting excludes Python object overhead and transient training autograd workspace. Snapshot construction rejects a mixed set of fractional floats and non-float64-representable integer times rather than silently rounding a persisted time tensor.
- JetMemory is a focused kernel module with a cloned rate buffer, not a trained reader or full MemoryMethod read implementation. Rates remain differentiable through external inputs; Task11 owns rate parameterization, task/query feature augmentation, reader/fallback, inference snapshot detachment and full parameter accounting. No serialization or clean-worker read isolation is claimed by this task.

Task4 round-1 validation boundary: `jet_step` and `laguerre_step` preserve signatures and now assume prevalidated finite tensors, with delta on state dtype/device. Neither performs scalar extraction, validation reductions or CPU exceptional-gap decisions. `validate_jet_step(state,key,value,gate,delta,rates,event_present)->None` is the explicit host validator for untrusted direct callers. JetMemory instead validates the whole raw batch, converted gates and incoming state before the loop; it prepares ordinary device gaps once and, only for unrepresentable huge durations, prepares differentiable coefficients outside the core. The shared tensor-only jet update consumes these prepared coefficients in the exceptional path. This fixes a synchronization boundary, not a new timing or throughput claim.
