# Baseline input conventions and implementation provenance

## Translated-Legendre memory — Task 13, 16 October 2026

`famjet/memory/hippo.py` independently implements the finite Leg-T equations in the binding specification §8. It does not vendor third-party source. The source reconciliation is R07, Goffinet, Hanks and Carlson, [HiPPO Zoo v2](https://arxiv.org/html/2602.21340v2#A4.SS3), cutoff 13 October 2026. Source identity was verified in the [source ledger](research/2026-10-16-source-verification.md): repository `jackgoffinet/hippo-zoo`, commit `04e38b3cf246f4c50cb6c6a7e10597e2e37eebc7`.

The [Leg-T generator and reconstruction](https://github.com/jackgoffinet/hippo-zoo/blob/04e38b3cf246f4c50cb6c6a7e10597e2e37eebc7/src/mpm/polynomials.py#L75) have blob `efaca78a15cba574ef6017e6a195127b0cf00834`. At order2, `A=[[-1,sqrt(3)],[-sqrt(3),-3]]`, `b=[1,sqrt(3)]`. With age coordinate `s=0` at the present, the reconstruction basis is `sqrt(2i+1)(-1)^i P_i(2s-1)`. This is translated Legendre, not the separate scaled-Legendre system. Finite coefficient state does not imply exact sharp-window reconstruction or positive coefficients.

The pinned [multiscale script](https://github.com/jackgoffinet/hippo-zoo/blob/04e38b3cf246f4c50cb6c6a7e10597e2e37eebc7/scripts/multiscale_hippo.py) has blob `38f3efb7f5a3f2538cc4ce284b931770086e655e`; its sampled-signal convention uses the augmented-matrix ZOH input. The actual Task13 comparator receives event mass: `P_new=expm(A*Delta/tau)P_old+(b/tau)X`. Its fixed writer uses the identical raw nonnegative key/gate and signed numeric value augmented with1. Each bank has its own positive static tau and integer order; their coefficients are concatenated with no padded/unused states. Scalar order/tau construction is shorthand for a one-bank allocation. A separately named `zoh_transition` computes the sampled constant-signal interval input by augmented exponential. At zero gap, an event adds its full impulse while ZOH adds zero. Independent quadrature and constant stationary reconstruction controls verify both conventions; they must not be scored against each other's target.

State coefficients use physical inverse-time units. Generic contracted readers see every query-key-contracted coefficient; generic full readers see all key/value coefficients. Both receive `t_ref*P` and identical public query key/task/dimensionless age endpoints. Neither divides signed coefficients by a positive-mass normalizer. Numerical support means finite features in a valid nonempty snapshot, including finite zero coefficients; it does not certify factual key/window support. Nonfinite features retain failure evidence. Task17 still owns uniform failure/fallback/scoring and calibrated abstention.

`SnapshotMemory` shares only snapshot identity, exact host-time handling, stream ownership and public query scaffolding. Existing jet/bank diagonal propagation remains its specialized subclass. Every polynomial stream step is a native tensor matrix multiply. Terminal encoding uses exact chunked impulse sums with full value/key/gate gradients; causal learned writers remain a separate optional arm. Timescales are fixed configuration values, not learned parameters.

CPU NumPy/SciPy FP64 constructs generators, injection vectors and propagators. Only declared gap matrices persist as registered buffers, in the state precision; native CPU/MPS FP32 propagates the state. This explicit host computation is not framework MPS fallback. Arbitrary gaps are prepared afresh, transferred explicitly, and never stored in a persistent memo table. `prepare_transition` returns local host preparation time and work; `call_preparation_cost` inventories all fresh encode/read forward gaps, including padding and the second advance for a generic-full read. Training wall time includes host preparation; logged work is explicitly forward-only because checkpoint recomputation can repeat it during backward. `matrix_cubic_work` is a dimension-based work proxy, not an exact FLOP count. Matrix construction and complete-model construction timing are separately reported. No throughput advantage is claimed.

For orders `n_a`, state payload bytes are `B*sum(n_a)*K*(V+1)*itemsize`; normal snapshot metadata is unchanged. Cache bytes are `len(declared_gaps)*sum(n_a**2)*itemsize`, injection bytes `sum(n_a)*itemsize`. Static buffers count separately and in end-to-end totals. Defaults declare gaps0/1/2/4/16; setting an empty alphabet with cache_limit_bytes0 disables persistent transition storage. Cache demand is checked before construction. Allocation/schema bounds are implementation safety bounds, not a scientific frontier selection: at most64 banks/gaps, order256 and total1024 coefficients. Smoke training retains the existing small envelope and allows at most8 coefficients, matching four jet anchors' payload. Non-smoke calibration/tuning remains Task18/20.

`configs/polynomial-smoke.yaml` declares orders4/4, taus16/128, FP32, generic contracted width128/two layers,1024 cache bytes, and the unchanged two-step CPU smoke policy. These timescales are executable plumbing settings, not tuned or development-selected settings. The cache uses640 bytes and the injection32 bytes. B1/K16/V8 payload is4608 bytes with129 metadata bytes, the same payload/metadata as J4 jets. Reader weights and work remain separately counted; equal width is not equal parameter cost.

Task14's stronger log-rate construction is still future: it must use the pinned script's finite Jacobi `G`, analytic Bessel beta, rotated injection and all `n*m` coefficients. This Task13 independent tau bank does not claim to implement that system. No comparative task-quality gain, convergence verdict, or protected scoring follows from these numerical and smoke controls.
