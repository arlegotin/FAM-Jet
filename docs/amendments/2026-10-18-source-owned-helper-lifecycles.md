# Trusted-source lifecycle accounting for bounded experiments

Adopted18October2026 following the [independent architecture ruling](../research/task18-stage-a-helper-architecture-report.md) and [stopped03 evidence](../research/task18-kernel-stage-a-stopped03-report.md). This authorizes one source implementation and independent review, including preparation of a new static native control. It authorizes no native invocation, scientific retry or protected work.

The scientific goal is truthful bounded resource accounting and isolated snapshot reads. The current sampled image/display rule cannot guarantee continuous executable identity or adversarial containment. Legitimate short-lived source-owned helpers may finish before kernel-image lookup, and a positive RSS sample may overlap actual completion. A terminal-spelling whitelist is an inappropriate ownership contract. Preserving that policy would leave the experiment limited by measurement compatibility; changing it requires an explicit trust boundary, adopted here.

Use one coherent source-owned generation registry across the finite declared operation families. Preserve exact family-specific commands, owners, parent generations, prelaunch executable artifact hashes, launch IDs/PIDs/times, source journal/offset and matching actual owning completion from the same retained Popen. Covers ordinary observer ps, numeric cleanup ps, the two authority Git commands and the existing single clean reader. Keep the accepted directly owned root receipt unchanged.

For an unambiguous numeric sample whose interval overlaps the exact declared lifetime, ordered genuine native ESRCH may be attributed through that lifecycle with arbitrary retained display and nonnegative integer RSS. No earlier live image is required for a fast helper; final attribution requires actual matching reap/completion. Pending evidence receives no certification. Contradictory successful images, malformed/native failures other than the existing ordered ESRCH, impossible chronology, rows wholly outside the source lifetime, undeclared PID reuse, duplicate IDs/PIDs, cross-family claims, wrong parents/vectors/artifacts, source gaps and conflicting ends remain failures. Source-reported versus supervisor-owned evidence stay distinguishable. This is attribution under reviewed trusted source, not adversarial PID-reuse exclusion or kernel-image proof. Never label unavailable images kernel_image, and never clear genuine contradictions after later evidence.

Charge every observed helper RSS fully, including stale positive/cleanup samples, with zero baseline credit and unchanged peak aggregation/caps. A missed fast helper has no measured peak, not demonstrated zero cost. Reader lifecycle attribution does not grant baseline subtraction: genuine reader SELF/live-image/baseline, clean process launch, closed numeric request, candidate/deadline and result/read-count/isolation checks remain. Unknown children retain bounded evidence drain and then stop. No timing grace, delay, extra sampler, retry or budget increase.

Future ends retain actual returncode and reap from the real Popen; failures/timeouts remain failed operations even if attribution succeeds. Historical absent status stays absent. Root/helper/reader source identity, memory baseline and operation success are separate. Keep full raw records and all original numerical/resource/failure limits. The scientific package, memory recurrences, rates, frozen metadata, epsilon, fixtures,1e-12 bounds and failure scopes are unchanged.
