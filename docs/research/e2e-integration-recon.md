# End-to-end PoC integration reconnaissance (bd3aa5a)

Read-only source and manifest inspection; no Torch import, protected labels, numerical run, or test was opened. This is an integration map, not an implementation acceptance.

## Immediate answer

A query-conditioned ridge reader is feasible on the fixed Jet4/Bank8 writer and the existing scoring API, but **the present `KernelReadModel` cannot deliver both workloads unchanged**. `KernelProjection` itself accepts small FP64 rate bases, computes ridge coefficients for each age window, and returns explicit failure codes (`famjet/readers/kernel_projection.py:85-118,166-219`). The wrapper only admits fixed CPU64 K16/V8, requires training mean/contrast fallback metadata before construction, hardcodes V8 outputs and K16 query features, and does no reader training (`famjet/models/kernel_read_model.py:21-54,88-141`). Beijing is K12/V1 with FP32 one-hot input (`famjet/data/beijing.py:197-225`); native micrograms/m³ labels are distinct from normalized training labels. The underlying Jet/Bank constructors allow positive K/V (`famjet/memory/jet.py:189-204`, `famjet/memory/expbank.py:185-201`). Thus reuse the kernels and projection math, while implementing a dimension-aware trainable reader/wrapper and deterministic wire format. A new external `famjet_poc` package can leave the 53 frozen core files intact; it **cannot** pass through the existing isolated method registry without a new registered type (`famjet/eval/isolation.py:42-56,94-109,185-197`). Use a separately source-pinned worker/serializer for that PoC, or explicitly revise the core registry and accept a new core source hash. Do not present an external wire as existing `export_method` acceptance.

## Reusable execution and accounting

* Training-only statistics: `fit_target_statistics` in `famjet/eval/metrics.py:20-77` and the two-pass, identity-checked `TaskModel.fit_statistics` pattern (`famjet/models/task_model.py:253-313`). The projection model's metadata schema demands training split, writer/t_ref/target hashes and mean/contrast priors (`famjet/models/_schema.py:57-110`; `famjet/models/kernel_read_model.py:47-54`). Existing `train_model` is synthetic TaskModel-only: phase/resource checks reject Beijing and protected runs, and the smoke envelope caps length at 128 and queries at eight (`famjet/train.py:212-225`). Its `history_loss` gives equal task means per history, but rejects failed predictions rather than silently filtering (`famjet/train.py:120-148`). A new PoC trainer needs explicit finite, failure-aware behavior and fitted-reader gradients; the source-only projection is not a trained reader.
* `score_episode` is duck typed and can consume a model with `encode`, `read`, `persistent_nbytes`, and `target_statistics`; it streams each event, quarantines nonfinite state, and preserves every query (`famjet/eval/runner.py:27-101`). `score_predictions` replaces failed/nonfinite/unusable outputs with frozen training priors; its complete v2 row records target/support validity, numeric support, failure, fallback, raw/final predictions, normalized and native error (`famjet/eval/metrics.py:147-265`). `aggregate_scores` checks exact declared query inventory and produces task-native RMSE/MAE separately (`famjet/eval/metrics.py:268-351`). For Beijing, convert standardized predictions back with the sealed training mean/scale for micrograms/m³ reporting, while retaining standardized scoring rows and never mixing units; the query grid has 12 stations × 5 widths × 2 tasks (`famjet/data/beijing.py:197-229`).
* `state_ledger`, `model_ledger`, `budget_report` count logical state, backing storage, static weights, wire size, graph retention and eligibility (`famjet/eval/budgets.py:1-6,57-75,93-135`). The projection wrapper adds reachable Python objects and query-copy estimate but explicitly does not measure allocator/process RSS (`famjet/models/kernel_read_model.py:143-171`). Measure actual process/descendant peak RSS under the <400 MiB run cap in the new runner; never infer it from tensor bytes. Existing `isolated_read` uses a clean `-I` worker, strict export, source/model hashes and snapshots (`famjet/eval/isolation.py:340-374`), useful as a design pattern but inaccessible to an external model.

## Honest release and report boundary

The package source hash covers **every `famjet/**/*.py` file**, so any core edit invalidates the source identities of checkpoints/analysis, while an external package leaves that core hash unchanged and needs its own pinned source/lock identity (`famjet/eval/isolation.py:53-56`; `famjet/train.py:176-203`; `famjet/analysis/statistics.py:323-335`). `pyproject.toml:12-16` packages only `famjet*` and runs tests in `tests`; an external package needs its own packaging/test entry. Existing checkpoint evaluation only supports exploratory `development_fit` and matching package/lock hashes (`famjet/train.py:498-567`). V2 scoring accepts no support calibration yet (`famjet/eval/metrics.py:170-173`). The confirmation analysis expects a frozen inventory, source/dependency/data/config/weight/statistics files, complete paired runs, release authorization, and matching score hashes **before** score parsing (`famjet/analysis/statistics.py:323-423`). `analyze_confirmation` then retains paired effects, draws, all scored rows, and blocked failures (`famjet/analysis/statistics.py:423-473`). `unfilled_calibration_policy` has null thresholds, outer N, domain, and streams; `evaluate_gate` fails closed until scoped independent calibration, implementation, resource, baseline and nuisance evidence pass (`famjet/analysis/statistics.py:193-296`). Prior B2000 reconnaissance undercovered at small paired seed counts; endpoint precision was insufficient as a validity test (`docs/statistical-protocol.md:58-66`). With 14 Beijing 56-day units, report finite-cluster limits rather than a universal power claim.

Minimal external API map: `famjet_poc/model.py` (dimension-aware trained reader, deterministic fallback/read), `wire.py` (strict source-pinned weights/statics + round-trip), `data.py` (v2 manifest checks and authorized protected split iterator), `run.py` (one command: prepare/fit/train/freeze/evaluate/release/analyze), `report.py` (replay from immutable rows/seals). Keep frozen core imports read-only. The one command should leave a final artifact listing each run/configuration, failures and fallback rates, normalized/native errors, owned/state/wire/RSS bytes, timing, exact asset/license/seeds/hashes, paired units/uncertainty and gate status. Protected execution should start only after the complete frozen manifest and source-bound acceptance exist; otherwise produce an explicit development-only report. Replay must verify hashes and regenerate the report without choosing a better run after seeing held-out rows.
