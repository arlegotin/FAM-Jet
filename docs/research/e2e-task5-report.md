## Interface and report behavior

- `__main__.py` parses without importing numerical packages, then calls the actual E4 pipeline or reporter.
- `report_inputs.py` verifies the E4 stage-ledger hash chain and every completed non-report stage file by streaming SHA-256. It ignores the mutable report stage when forming report content, so first render and post-completion replay have identical bytes. It rejects incomplete or extra scientific stages, incomplete method/cell pairs, changed row files, path traversal and symlink escape.
- Frozen paths remain byte-for-byte unchanged. The adapter maps references below the recorded original run root onto the supplied `--run` root, accepting E4's relative and absolute path forms. It separately allows only the pinned project-relative Beijing v2 manifest. It never globally patches `Path` or edits serialized releases. A copied test run replays after the original is deleted.
- Production validation checks frozen executable/model source identity, current qualification and accepted calibration evidence, frozen model round trips and pair/mode commitments, public 36-candidate/four-subset/six-control ledgers at both numeric shapes, timing/stress receipts, complete protected method and history inventories, grants, score policies, full-versus-eligible IDs, observed-count sidecars, live resource receipts and paired conditional inference. It reads one protected method/cell row file at a time.
- Both real transfer modes require 56 chronological blocks × 120 queries × eight methods, exact grants and native/normalized row pairing, training-only scoring statistics, observed-count sidecars, live guards, native value inversion, per-method RMSE/MAE and 28-/56-day descriptive block sensitivity. Recomputed paired sensitivity must match E4's release receipt. Real rows are processed one method at a time; only compact Jet/Bank paired block data are retained. Production schema logic is source-checked but was not executed against a full E4 run in E5.
- The scientific report writes deterministic Markdown, canonical JSON and canonical chart JSON. It displays every entered candidate/subset and failure status, controls, storage/timing/cost receipts, separate confirmation and replication, both real modes, secondary implemented/unsupported cells, prior failures, asset/license revision inventory and narrow decision limits. Unsupported/missing values are `null` with status; test-only releases are labeled `non_scientific_smoke` and carry no scientific conclusion.
- `plots.py` runs under a separate selected interpreter. It consumes only chart JSON, checks every installed package version against the separate hash lock, uses Agg and bounded temporary `MPLCONFIGDIR` before Matplotlib import, fixes DejaVu Sans and `svg.hashsalt`, omits SVG Date metadata, and writes accuracy/state, full-static/read-cost and separate effect SVGs plus renderer/data/package/output hash receipt. The reporter requires all chart outputs and their hashes before publishing a scientific Markdown file. `FAMJET_REPORT_PYTHON` takes precedence, then `.report-venv/bin/python`, then the current interpreter if Matplotlib is installed; a missing dependency fails report completion.

The raw run remains the authority. The reporter does not fit, select candidates, generate histories or recalculate protected targets. Its original/copy verification uses E4's `validate_scored_receipt`, `AccessGrant.verify`, E3 row/model loaders and E2 paired interval functions on path-resolved in-memory references. The E4 helpers used here are a pinned internal coupling; a future E4 schema change must be reviewed before report replay.
