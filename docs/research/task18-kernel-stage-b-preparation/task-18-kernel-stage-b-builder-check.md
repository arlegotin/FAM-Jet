The emitted `ReadResult` has predictions, failures and diagnostics but **no query IDs** (`famjet/types.py:83–90`); `isolation._result_record` also has no IDs (`famjet/eval/isolation.py:283–309`). Therefore the design's “check returned ... exact query identity” cannot be implemented from the existing response. Freeze and hash the eight-query request/manifest order, verify each input query ID once and the returned `[1,8,8]` / `[1,8]` positional shapes, and bind the immutable raw response to that request hash. State explicitly that `_result_from_record` is worker-internal; the Stage B adapter must decode the guarded worker's `numeric` JSON (where nonfinite values become `null`) without inventing echoed identities or changing the worker schema. A response identity echo would require a separately reviewed worker change and is outside this design.

2. **Specify the quarantine precedence.** `score_episode` stops encoding at the first nonfinite stored field and does **not** call `read` for that history (`famjet/eval/runner.py:48–93`). Its eight rows use nonfinite raw predictions, `failure=true`, `prediction_valid=false`, `numeric_supported=false`, `quarantined=true` and the retained trigger. Stage B should do exactly this for an encode trigger, including saved-state/logical-byte evidence; `diagnostics.quarantined` from `KernelReadModel.read` (`famjet/models/kernel_read_model.py:103–141`) applies only to a response from a read that actually occurred. Reader exceptions, malformed output, missing counters, and transport failures stop as infrastructure failures. This clarification prevents an attempted worker read or fabricated numerical fallback after an encode trigger.
