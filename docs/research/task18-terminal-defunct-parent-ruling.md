# Root builder decisions for terminal-row proposal v2

18 October 2026. The independent builder review found one blocking ambiguity: which Python parent generation can authorize a terminal observer-helper row, and how pending rows react to parent evidence. Root accepts that finding. This is a design correction only, not adoption, implementation or execution permission.

Use a finite, acyclic relation: PS helper → exactly one accepted root or reader generation, or direct owning supervisor. Bind the helper's exact source launch parent PID to that Python generation's launch ID; require parent.launch_start <= helper.launch_start and, if a parent completion exists, helper.launch_start < parent.completion_end. Keep the helper's existing raw-parent consistency check; this proposal does not admit a reparented helper by inventing a new raw PPID. Reject failed/conflicting parent generations and observed contradictory identity/release/reuse. No parent is selected solely by its PID or a declared launch.

The parent must have an applicable successful historical Python proof ending no later than the helper terminal sample starts. Use the established origin: unreaped owning-supervisor root proof, or genuine reader emitter=self SELF plus post-import/pre-allocation baseline join. A live qualified parent needs no completion. An absent parent may qualify from those exact historical witnesses and compatible source lifetime; record that this is source-only historical parent attribution, not a current OS observation. If the parent is present as a terminal row in the same sample, that row must satisfy the complete terminal contract (including genuine end) before it qualifies its helper. Thus parent-before-child versus child-before-parent iteration cannot change the result; classify root/reader evidence first, then PS helpers. There are no helper-to-helper parent chains.

Pending helper observations depend both on their own generation and on the bound parent generation. Index and wake affected observations on relevant parent launch/proof/SELF/baseline/end/failure changes as well as their own witnesses. Missing parent launch is pending under existing bounds; ambiguous/contradictory parent evidence is failure. No unbounded scan or new grace. Incomplete provenance and known failed identity can never become qualifying evidence.

Root-only cleanup qualification is provisional before the actual owning poll: complete membership has exactly the root, integer RSS0, current retained literal terminal row plus all terminal prerequisites except its still-missing owning completion, and the owner is still unreaped. Final qualification requires actual owning poll/wait0 and truthful end, then terminal reconciliation. Preserve a distinct `qualified_terminal_root_only` record with membership_empty=false. It is not an empty-group certificate. Nonroot survivors, missing prerequisites, poll=None or earlier violations do not pass. Required cancellation is still attempted while ownership is held and never receives a fresh deadline.

Why: this addresses the actual macOS terminal-display loss without weakening exact live-vector admission or borrowing arbitrary PID proofs. It explicitly permits the useful historical-parent case with disclosed source-witness limitations. Cost if wrong: false attribution could undercharge a foreign process; focused negative and evidence-order tests and separate native validation must precede scientific release. No current-identity, birth-token or security-containment claim is allowed.

The architect should integrate these choices in a separately preserved v2 proposal, referring to the original unchanged full four-family contract. The same independent builder reviewer then checks only resolution of its blocker and breakage from this correction. All numerical, resource, information-access, failure, timing, selection and protected-access constraints remain fixed.
