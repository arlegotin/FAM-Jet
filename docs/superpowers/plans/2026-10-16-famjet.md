# FAM-Jet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a reproducible local experiment that decides whether exact first temporal moments improve deferred temporal queries at fully measured resource budgets.

**Architecture:** Independent causal encoders produce immutable, versioned snapshots; numeric readers receive only snapshots and later queries. Exact raw-event oracles, equal-byte and modern memory families share manifests, metrics, failure handling, and cost accounting. Development, pilot, protected confirmation, real transfer, and optional extensions are separate gates.

**Tech Stack:** Native-arm64 CPython selected by actual compatibility; NumPy/SciPy CPU references, PyTorch CPU/MPS FP32 training, pytest, PyYAML, standard-library JSON/hash utilities and packed NumPy arrays; optional matplotlib for reports. Resolve exact versions and wheel hashes at Task 1.

**Spec:** [FAM-Jet technical specification](../specs/2026-10-16-famjet-design.md). Read it with the [source ledger](../../research/2026-10-13-source-record.md) and [observed target](../../research/2026-10-16-local-environment.md).

## Global Constraints

- Research cutoff remains **13 October 2026**; implementation specification prepared 16 October 2026.
- No remote GPU, paid model API, additional machine, custom GPU kernel, vector database, numerical ODE solver, or pretrained language model is required by the core.
- Historical writes never see eventual queries. Queries are generated after the entire history.
- Persistent bytes include **all history-dependent information surviving between events or queries**.
- FP64 CPU is the oracle. Lower-precision states are a separately registered frontier experiment.
- Native MPS runs set `PYTORCH_ENABLE_MPS_FALLBACK=0` before torch import and keep reference fast-math off.
- No system upgrade is authorized. Preserve allocator protective limits.
- Unsupported/nonfinite predictions fall back to the training-only unconditional task mean, retain a failure flag and full resulting loss.
- One development-selected primary pair/budget gets one primary two-sided 0.05 comparison.
- Changes to hypotheses, information access, population/splits/metrics, precision/state capacity, baseline architecture, stopping, or interpretation require a dated methodological amendment and fresh protected data when necessary.
- Work on the current branch, `main`; do not create a worktree or change branch. The user explicitly requested this workflow.
- This document specifies future work. No checkbox is completed by writing this plan, and no proposed project command currently exists.

## Review Focus

- Query T precedes snapshot time: reject the read; build a causal prefix instead of allowing negative decay or future leakage (Tasks 4, 10).
- Padding contains garbage/NaN values: reject nonfinite public inputs or sanitize them before multiplication; `0*NaN` must not corrupt valid histories (Tasks 2, 4).
- A snapshot is reused after rates/writer parameters change: reject its parameter hash and recompute, including after checkpoint reload (Tasks 10–12).
- Scalar real data has missing/all-missing hours and tied station timestamps: omit missing measurements, advance public time, preserve stable ordering and split boundaries (Task 7).
- A comparison is interrupted or one method fails: completeness comes from the immutable expected-run manifest, failed-query loss remains included, and no protected scores appear early (Tasks 12, 17, 21).
